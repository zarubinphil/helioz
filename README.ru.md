## Что это

Helioz это конвейер для работы агентов. Вы один раз говорите, что нужно. Он допрашивает вас, пишет планы, раздаёт задачи агентам, проверяет результат вторым агентом и отчитывается. Работает на вашем компьютере, всё состояние лежит на диске.

## Зачем это нужно

Агент забывает задачу между сессиями, говорит «готово», когда не готово, и будит вас ночью из-за мелкой развилки. На каждую из этих бед у Helioz есть прибор: состояние на диске, слепой проверяющий и ночной совет. К утру у вас движение, а не замерший чат.

## Главное преимущество

**Главное преимущество:** отметку о готовности пишет код, а не тот агент, который делал работу.

**Почему это лучше:** в отметке лежат коммиты до и после, хеш изменённых файлов и код возврата проверочной команды, поэтому скопированную или написанную руками отметку видно и о ней говорят вслух.

## Как это работает

Такт крутится по кругу. Каждый шаг оставляет файл на диске, поэтому убитая сессия продолжает с той же строки.

<!-- workflow-diagram:start -->

```text
  ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ Допрос   │ ▶ │ План     │ ▶ │ Ворота   │
  └──────────┘   └──────────┘   └──────────┘
        ▼
  ┌──────────┐   ┌──────────┐   ┌──────────┐
  │ Работа   │ ▶ │ Проверка │ ▶ │ Отметка  │
  └──────────┘   └──────────┘   └──────────┘
        ▼
  ┌──────────┐
  │ Передача │
  └──────────┘
```

<!-- workflow-diagram:end -->

| Этап | Что происходит |
|---|---|
| 1. Допрос | Одна фраза превращается в заполненные слоты и записанную цель |
| 2. План | Два независимых плана, которые сводит третий агент |
| 3. Ворота | Слоты, зависимости, бюджет и рубильник «стоп» |
| 4. Работа | Живая проба CLI выбирает агента, который реально работает |
| 5. Проверка | Второй агент читает диск, а не отчёт |
| 6. Отметка | Коммиты, хеши файлов и код возврата внутри отметки |
| 7. Передача | Отчёт в Telegram, ночной совет по мелким развилкам, свежая сессия |

### Шаг 1: Скажите цель один раз

Вы начинаете с одной фразы о намерении. Helioz задаёт по одному вопросу и прикладывает свою рекомендацию, так что согласиться можно одним словом. Отвечать можно в редакторе, в терминале или в Telegram.

**Что получится:** цель в `queue/GOAL.md`, по которой сверяется каждое следующее решение.

### Шаг 2: Двое планируют вслепую

Два агента пишут планы, не видя друг друга. Третий сводит их вслепую. Один умный агент любит собственные ошибки, а двое спорят.

**Что получится:** мастер-план и мелкие задачи в `queue/tasks/`, у каждой своя проверочная команда.

### Шаг 3: Ворота берут следующую задачу

Ворота берут только ту задачу, у которой закрыты зависимости и осталось место в бюджетном окне. Двое агентов не возьмут один файл: код откажет второму.

**Что получится:** одна взятая задача с закреплённым набором файлов и живым счётом бюджета.

### Шаг 4: Исполнитель делает работу

Перед выдачей работы Helioz гоняет живую пробу каждого агентского CLI, а не верит строке версии. Задача уходит тому, кто ответил.

**Что получится:** изменённое рабочее дерево и лог того, что агент действительно запускал.

### Шаг 5: Слепой проверяющий сверяет

Проверяющий не видит отчёт исполнителя. Он смотрит файлы, запускает проверочную команду и добавляет враждебную пробу. Свою работу здесь никто не оценивает.

**Что получится:** вердикт, подкреплённый выводом команды, либо задача, отправленная на доработку.

### Шаг 6: Код пишет отметку о готовности

Отметку пишут ворота, а не агент. Тринадцать враждебных проб пытаются её подделать: скопированная расписка, отметка без внешнего коммита, переписанный лог, подменённая проверочная команда.

**Что получится:** задача, закрытая доказательством, которое переживает разбор.

### Шаг 7: Отчёт, совет, передача

Ход работы уходит в Telegram и на диск. Мелкая развилка идёт в совет из четырёх линз: они пишут порознь, а решение сверяется с вашей целью. Продакшн, столкновение с чужой работой и дорогие развилки всегда ждут вас.

**Что получится:** файл передачи, по которому сторож поднимает следующую сессию без потери контекста.

## Быстрый старт

Нужны macOS или Linux, Node.js 20 или новее, git и хотя бы один агентский CLI: `claude`, `codex` или `kimi`. Заходить можно любым из трёх путей.

```bash
git clone https://github.com/zarubinvibe/helioz.git ~/helioz
cd ~/helioz
bash install.sh en
bash scripts/helioz-start.sh
```

Нет Git? Скачайте [ZIP](https://github.com/zarubinvibe/helioz/archive/refs/heads/main.zip), распакуйте и запустите внутри тот же `bash install.sh en`. Привыкли к архиву из терминала? Возьмите [tar.gz](https://github.com/zarubinvibe/helioz/archive/refs/heads/main.tar.gz). Первый раз? Откройте проект в Claude Code и запустите `/helioz-setup`: установка пройдёт разговором, по одному вопросу, и ничего не поставится без вашего «да».

Делаете это впервые? [Онбординг](docs/ONBOARDING.ru.md) проводит весь первый запуск по шагам и говорит, что видно после каждой команды.

**Что получится:** установщик представляется, проверяет Node, git и ваши агентские CLI, гоняет селф-тесты приборов и называет то, что осталось сделать руками.

## Простое сравнение

| Вариант | Когда подходит | Что получаете | Минус |
|---|---|---|---|
| **Helioz** | Долгая работа должна идти, пока вас нет | Состояние на диске, слепая проверка, неподделываемые отметки, ночные решения | Запускаете и присматриваете сами |
| Агент руками | Одна короткая задача за один присест | Полный контроль каждого шага | Работа встаёт, как только вы закрыли ноутбук |
| CI-пайплайн | Повторяемые проверки после коммита | Прогоны на сервере и история | Реагирует на коммиты, но не планирует и не решает |
| Трекер плюс чат с агентом | Координация команды | Видимая доска и комментарии | Никто не проверяет, правда ли «сделано» |

## Безопасность и приватность

- Доступ к файлам не выходит за пределы клона, пока задача не назовёт другой разрешённый путь.
- `.helioz/`, `queue/` и логи это локальное рантайм-состояние, наружу они не уходят.
- Секреты лежат вне git и читаются только в момент отправки или опроса.
- Доставка в Telegram это best effort: сообщение сначала ложится в локальный outbox.
- Продакшн-действия и дорогие развилки совет отклоняет, они ждут вас.
- Пустая очередь, нечитаемое состояние или совет без цели это красный результат, а не пропуск.

Перед любым push просмотрите `git diff` и прогоните публичный gate.

## Ограничения

Статус: рабочая локальная система, автор гоняет её каждый день.

- Только macOS и Linux, пути под Windows нет.
- Качество работы это качество того агентского CLI, который вы поставили.
- Ворота доказывают состояние файлов и вывод команд, но не оценивают продуктовый вкус.
- Telegram, ночной совет и сторож необязательны, их можно выключить.

Глубже: [полный разбор](docs/DETAILS.ru.md), [контракты состояния](docs/CONTRACTS.md), [промпт оркестратора](ORCHESTRATOR.md) и [мастер-план](docs/MASTER-PLAN.md). Доказательство сказанного выше: `node scripts/helioz-probes.mjs` гоняет тринадцать враждебных проб, и все они должны быть зелёными.
